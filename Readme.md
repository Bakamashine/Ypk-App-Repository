# YPK Management API

## Описание проекта

YPK Management API -- RESTful веб-приложение, разработанное для управления продуктами, заказами, пользователями и отзывами в рамках системы управления бизнес-процессами. Система поддерживает ролевую модель доступа с тремя уровнями прав: администратор, менеджер и обычный пользователь.

## Технологический стек

| Технология | Назначение |
|---|---|
| .NET 6.0 (C#) | Платформа разработки |
| ASP.NET Core Web API | Веб-фреймворк |
| Entity Framework Core 6.0 | ORM для работы с базой данных |
| MediatR 11.1 | Реализация паттерна CQRS |
| FluentValidation 11.5 | Валидация входящих запросов |
| AutoMapper 12.0 | Маппинг DTO и команд |
| Serilog 2.12 | Структурированное логирование |
| SixLabors.ImageSharp 3.1 | Обработка изображений |
| BCrypt.Net-Next 4.0 | Хеширование паролей |

## Архитектура

Проект построен по принципу чистой архитектуры (Clean Architecture) и состоит из четырёх слоёв:

- **Domain** -- доменная модель, содержащая сущности бизнес-логики без внешних зависимостей
- **Core (Application)** -- уровень приложений, реализующий паттерн CQRS через MediatR, DTO, интерфейсы, валидаторы и маппинги
- **Persistence** -- уровень доступа к данным, реализованный на базе Entity Framework Core с конфигурацией сущностей
- **Presentation** -- уровень представления, включающий контроллеры API, промежуточное ПО и конфигурацию зависимостей

## Функциональные возможности

### Аутентификация и авторизация

- Регистрация и вход по номеру телефона и паролю
- JWT access-токены (срок действия -- 5 минут)
- Refresh-токены (срок действия -- 7 дней) с хранением в cookie
- Выход из системы и повторная аутентификация через токен
- Ролевая авторизация: Admin, Manager, DefaultUser

### Управление пользователями

- Полные CRUD-операции для учётных записей
- Загрузка аватара пользователя
- Назначение ролей и привязка к подразделениям YPK (только администратор)
- Получение информации о текущем пользователе

### Управление продуктами

- Создание, редактирование и удаление продуктов
- Привязка продуктов к подразделениям YPK
- Статусы продуктов: опубликован, удалён, на редактировании
- Загрузка фотографий с автоматическим изменением размера (максимум 1200x1200) и сжатием в JPEG
- Фильтрация и пагинация списков продуктов

### Управление заказами

- Создание и управление заказами
- Привязка заказов к покупателю, продукту и исполнителю
- Статусы заказов: отменён, размещён, в работе, готов к выдаче, принят
- Раздельные представления заказов для менеджеров и пользователей
- История заказов для обеих ролей

### Управление подразделениями YPK

- CRUD-операции над подразделениями
- Создание и удаление доступны только администратору

### Система отзывов

- Отправка отзывов с текстом, оценкой (1-5) и изображениями
- CRUD-операции над отзывами

### Работа с файлами

- Локальное хранение файлов с организацией папок по датам
- Валидация изображений (максимум 5 МБ, форматы JPG/PNG)
- Автоматическое изменение размера и сжатие изображений

## Структура проекта

```
Ypk-App-Repository/
├── Domain/                     # Доменный слой (сущности)
├── Core/                       # Слой приложения (CQRS, DTO, интерфейсы)
│   ├── Commands/               # Команды (запись данных)
│   ├── Queries/                # Запросы (чтение данных)
│   ├── Dtos/                   # Объекты передачи данных
│   ├── Behaviors/              # Поведения MediatR
│   ├── Interfaces/             # Абстракции
│   ├── Repository/             # Репозитории
│   ├── Exceptions/             # Пользовательские исключения
│   └── Mappings/               # Профили AutoMapper
├── Persistance/                # Слой доступа к данным
│   ├── ApplicationDbContext.cs # Контекст EF Core
│   └── EntityFrameworkConfiguration/  # Конфигурации сущностей
└── Presentation/               # Слой представления (Web API)
    ├── ProductsWebApi/
    │   ├── Controllers/        # Контроллеры API
    │   ├── Services/           # Реализации сервисов
    │   ├── Middleware/         # Промежуточное ПО
    │   └── wwwroot/uploads/    # Хранилище файлов
    └── Services/
```

## Требования к окружению

- .NET 6.0 SDK
- PostgreSQL (для продуктивной среды) или SQLite (для разработки, создаётся автоматически)

## Установка и запуск

### Сборка проекта

```bash
dotnet build Presentation/ProductsWebApi/ProductsWebApi.csproj
```

### Запуск в режиме разработки

```bash
dotnet run --project Presentation/ProductsWebApi/ProductsWebApi.csproj
```

### Использование Makefile

```bash
make build    # Сборка проекта
make dev      # Запуск в режиме разработки
```

## Конфигурация

| Параметр | Среда разработки | Продуктивная среда |
|---|---|---|
| База данных | SQLite (автоматически) | PostgreSQL |

## Документация API

После запуска приложения документация Swagger доступна по корневому URL приложения (например, `https://localhost:7001`).

Схема OpenAPI: `/swagger/v1/swagger.json`

## Обзор API-эндпоинтов

| Контроллер | Методы | Описание |
|---|---|---|
| Auth | POST/GET | Аутентификация, регистрация, управление сессиями |
| User | GET/POST/PUT/DELETE | Управление пользователями |
| Product | GET/POST/PUT/DELETE | Управление продуктами |
| Order | GET/POST/PUT/DELETE | Управление заказами |
| Ypk | GET/POST/PUT/DELETE | Управление подразделениями |
| Feedback | GET/POST/PUT/DELETE | Управление отзывами |
| Role | GET | Получение списка ролей |
| StatusOrder | GET | Получение статусов заказов |
| StatusProduct | GET | Получение статусов продуктов |

## Логирование

Проект использует Serilog для структурированного логирования. Логи выводятся в консоль и записываются в файлы с ежедневной ротацией. Срок хранения логов -- 30 дней. Через MediatR pipeline behavior выполняется логирование каждого запроса с идентификатором пользователя.

## Инициализация базы данных

При первом запуске приложение автоматически применяет миграции и заполняет справочные данные:

- Роли пользователей (Admin, DefaultUser, Manager)
- Статусы заказов (Отменён, Размещён, В работе, Готов к выдаче, Принят)
- Статусы продуктов (Опубликован, Удалён, На редактировании)

## Развёртывание

Приложение является самодостаточным ASP.NET Core приложением и может быть развёрнуто на любой платформе, поддерживающей .NET 6.0:

- IIS (Windows)
- Kestrel (Linux/Windows)
- Облачные платформы (Azure, AWS и другие)

Для продуктивной среды необходимо указать строку подключения к PostgreSQL в файле `appsettings.json` или через переменные окружения. Статические файлы обслуживаются из директории `wwwroot/uploads/`.
